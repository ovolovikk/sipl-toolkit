# Дерево синтаксичного виводу

`sipl tree <файл>` будує дерево виводу програми за БНФ: внутрішні вузли — метазмінні
(`<оператор>`, `<вираз>`, …) з назвою правила (`NS4`, `NA5`, …), листки — термінали.
Кожен вузол знає свій фрагмент коду: позицію і текст.

```
<програма> NP1  1:1  begin…
├── begin
├── <оператор> NS2  2:3  R := 1;…
│   ├── <оператор> NS1  2:3  R := 1
│   │   ├── <змінна> NV  2:3  R
│   │   │   └── R
│   │   ├── :=
...
└── end

Листки зліва направо: 1 begin 2 R 3 := 4 1 5 ; 6 while 7 Y 8 > 9 0 10 do ... 24 end
```

Останній рядок — перевірка синтаксичної правильності, як у практикумі: листки, прочитані
зліва направо, мають дати текст програми. Тести перевіряють це для кожного вузла кожної
коректної програми з `tests/fixtures/valid`.

Формати:

| Параметр | Вивід |
|---|---|
| — | текст, як вище |
| `--json` | `{"ok":true,"tree":{"symbol":"<програма>","rule":"NP1","span":{...},"children":[...]}}`, листки — `{"token":"begin","span":{...}}` |
| `--dot` | Graphviz: `sipl tree файл --dot \| dot -Tpng > tree.png` |
| `--svg` | готова картинка; листки пронумеровані, при наведенні на вузол видно його фрагмент коду |

Приклад SVG для `examples/power.sipl`: [`power-tree.svg`](power-tree.svg).

Дерево будується з AST і токенів: дужки та ключові слова беруться з токенів, тож
дерево точно відповідає тому, як програму розібрав парсер (`src/parse_tree.rs`).
