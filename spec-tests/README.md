# Тести специфікації

66 програм з очікуваним результатом. Вони запускають `sipl` як чорну скриньку і
перевіряють лише JSON-вивід з [`docs/cli.md`](../docs/cli.md), тож ними можна
перевірити будь-яку реалізацію SIPL з таким самим командним рядком.

```bash
pwsh scripts/spec-tests.ps1                     # ця реалізація
pwsh scripts/spec-tests.ps1 -Sipl шлях/до/іншої  # інша реалізація
```

## Формат

Кожен тест — `NAME.sipl` і поруч `NAME.json`:

```json
{
  "command": "run",
  "state": { "X": 2, "Y": 10 },
  "expect": { "ok": true, "state": { "R": 1024, "X": 2, "Y": 0 } }
}
```

- `command` — `parse`, `check`, `run` або `trace`;
- `state` — початковий стан (необов'язково);
- `max_iterations` — ліміт циклів (необов'язково, для тестів на зациклення);
- `expect` — очікуваний JSON.

## Як порівнюється

`expect` має міститися у виводі: зайві поля у виводі ігноруються, масиви мають
збігатися за довжиною. Тексти повідомлень не перевіряються, у помилках — лише місце.
Код завершення має відповідати результату: `0` — успіх, `1` — синтаксична помилка,
`3` — помилка виконання.

## Групи

`parse` (18), `syntax-errors` (20), `run` (15), `runtime-errors` (5), `trace` (8).
